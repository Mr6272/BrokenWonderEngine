# 复雷加殊 Complexweeper · 规则契约（本项目唯一事实来源）

目标：给 `web/examples/扫雷.bwproj` 增加第二种玩法模式，HUD 多一个按钮在「普通 / 复雷加殊」之间切换。
参考：B 站视频 BV1DMHZ6BEak「复 雷 加 殊」，作者 Solitude_Root3。

## 1. 什么是复雷

普通扫雷的雷是「1 颗雷」。复雷把雷换成 4 种复数：

| 雷种类 | 值    | 视频里的颜色 |
|--------|-------|--------------|
| 实雷 + | +1    | 红           |
| 实雷 − | −1    | 蓝           |
| 虚雷 + | +i    | 紫           |
| 虚雷 − | −i    | 青           |

术语：`实雷` = 只有实部的雷（+1 / −1）；`虚雷` = 只有虚部的雷（+i / −i）。

## 2. 数字的含义

翻开一个非雷格后，它显示的数字 = **周围八个格子中所有雷所代表复数之和的模长**：

```
sum = (sumRe, sumIm) = Σ 8 邻域的雷值
n   = sumRe² + sumIm²
label = |sum| = √n
```

显示规则（`ComplexRules.label`）：
- `n` 是完全平方数 → 显示十进制整数（`0`、`1`、`2`、`3`…）；
- 否则显示 `√n`（`√2`、`√5`、`√8`、`√10`、`√13`…）。
- 模长恒 ≥ 0：`(−1,0)` 与 `(+1,0)` 都显示 `1`。

**核心机关**：显示 `0` 不等于周围没有雷 —— `+1` 与 `−1` 相邻即和为 `(0,0)`，同样显示 `0`。

## 3. 插旗（两模式一致）

右键在「无旗 / 有旗」之间切换 —— **旗子不带任何属性**，行为与今天的普通模式完全相同。
这直接对应视频底部的注释「\*不需标对每个雷的属性」：玩家不需要给每颗雷标注实/虚。
`flags` 的语义与今天一致（已插旗格子数），插旗不参与胜负判定。

## 4. 点击数字 = 连锁翻开（chord），仅复雷模式

左键点一个**已翻开且带数字**的格子，可翻开它周围所有**未插旗**的格子，当且仅当同时满足：

① **数量正确**：周围八格中已插旗格子数 == 周围八格真实雷数。

② **虚实比例正确**。记：
   - `fR` / `fI` = 周围**已插旗格中**「真实属性是实雷 / 真实属性是虚雷」的个数
   - `aR` / `aI` = 周围**真实雷中**「实雷 / 虚雷」的个数

   满足**任一**等式（交叉相乘，不做除法，因此不存在除零）：
   ```
   A（同向）: fR * aI == fI * aR
   B（反向）: fR * aR == fI * aI
   ```

两条都满足才翻开。`ComplexRules.ratioOk(fR,fI,aR,aI)` 就是这两个等式的实现。

**为什么 ② 不是多余的**：① 只保证「旗的数量」对，不保证「旗插在对的格子」。
② 用真实虚实构成做二次校验。而 ① 与 ②A 同时成立时，`fR+fI == aR+aI` 且 `fR/fI == aR/aI`
→ `fR == aR` 且 `fI == aI`，即**所有相邻真雷都已被正确插旗**（存在 aR 颗实雷却标出 aR 个实雷格，
只能是把它们全标了），不可能还漏着雷。这正是不需要给旗子加属性的原因。

**标满且标对时必然通过**：`fR==aR, fI==aI` → `A: aR*aI == aI*aR` 恒真。

**连锁的后果与普通扫雷一致**：若 ①② 被骗过、周围仍有未插旗的真雷，翻开即踩雷判负。

**普通模式不加 chord**：普通模式点已翻开的格子无反应（保持今天行为，零回归）。

## 5. 自动展开（0 格）

- 普通模式：数字 `0`（周围无雷）自动向 8 邻域展开（与现在一致）。
- 复雷模式：只有 **`sumRe==0 && sumIm==0`（周围真实雷为 0）** 才自动展开；
  显示 `0` 但实际有雷（±1 抵消）的格子**不展开**，不泄露信息。

## 6. 胜负

- 翻到任意雷格 → 判负。按现有 `revealAllOnLose` 亮出全部雷；复雷模式下在雷格上额外标出它的种类（`+1/−1/+i/−i`）。
- 翻开所有非雷格 → 判胜（与现有「清空所有安全格」一致）。

## 7. 布雷

- 首击保护沿用现有逻辑（点开格 + 8 邻不埋雷）。
- 复雷模式：候选格中随机选 `mineCount` 个，每个独立随机取 4 种雷之一（各 1/4）。
- 普通模式：雷值恒为 `+1`（`sumIm` 恒 0 → 数字与今天完全一致）。

## 8. 模式与接口（不新增成员名）

- 模块参数 `game.minesweeper.mode`：`"普通 Normal"` / `"复雷加殊 Complexweeper"`，默认普通。
  解析口径同本仓其它 pick 参数：值里含 `复雷` / `Complex` 即复雷模式，否则普通。
- `bwe.mine.set({ mode: "normal" | "complex" })`：切换模式并重建棋盘（与 rows/cols 同触发 reset）。
  也接受 `"普通"` / `"复雷加殊"`。
- `bwe.mine.state()` 增加字段：`mode`（`"normal"`/`"complex"`）、`modeIndex`（0/1）；
  `flags` 语义不变（已插旗格子数）。
- **不新增任何 `bwe.mine.*` 成员名** → `verify-apidocs` 的成员集合零变化。

## 9. 显示

- 数字（Java 侧 paint）：整数用现有 `numberColor(n)` 调色；带根号按 `n` 取色
  （`√2` 青、`√5` 深绿、`√8` 蓝、`√10` 紫、其它灰蓝），字号比整数略小（最多 3 字符）。
- 复雷模式的雷格（判负亮出时）：素材图 + 右下角小字标 `+1/−1/+i/−i`（红/蓝/紫/青）。
- 顶部 LED 与文案由脚本 `minesweeper.js` 负责；Java 只画棋盘。
- HUD：横屏底带在「新游戏」旁加一个「模式」按钮，点击在两种模式间切换并重建；
  竖屏底带在「重局」按钮上方/旁同样给一个模式按钮。按钮文案随当前模式变化。
- 复雷模式状态行显示当前模式与提示；普通模式显示今天的文案。

## 10. 验收

- `ComplexRules.label` / `ComplexRules.ratioOk` 行为与本文件第 2、4 节完全一致，
  由两方独立交叉验证：`python tools/gen-complexweeper-fixtures.py` 生成 `test/fixtures/complexweeper.json`；
  `ComplexMineRulesTest`（Java）读这份 fixtures 断言。
- 构建/自检全绿：`bwe.ps1 build`、`check-java8`、`typecheck`、`check-scripts`、`verify-apidocs`（不出现新的编造/未实现）。
- 引擎实跑：`bwe.ps1 offscreen <boot.json>` 出图，普通与复雷两模式都能画出来且互不串味。
- 玩法由**试跑**验证（本机 Java 窗口真跑 `scripts/minesweeper.js`），与 Java 侧同一份规则。
